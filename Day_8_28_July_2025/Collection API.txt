Collection API ->

	1) What is the Java Collection API?
		- The Java Collection API is a framework in the `java.util` package that provides data structures and algorithms to store, 
		  retrieve, and manipulate groups of objects efficiently.

	- Advantages of Collection API

| Advantage                    |  Description                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------|
| Reusability        	       | Ready-to-use data structures like `ArrayList`, `HashSet`, etc.                                                          |
| Interoperability             | All classes share common interfaces (`List`, `Set`, etc.), so you can easily switch implementations.                    |
| Built-in Algorithms          | Comes with sorting, searching, shuffling, etc., via `Collections` utility class.                                        |
| Type Safety (Generics)       | Supports generics, reducing runtime errors (e.g., `List<String>`)                                                       |
| Reduces Coding Effort        | No need to create your own data structures from scratch.                                                                |
| Scalability                  | Works well for small to large data sets.                                                                                |
| Thread-safe Options          | Thread-safe variants like `Vector`, `ConcurrentHashMap`, or synchronization wrappers (`Collections.synchronizedList()`).|


	- Core Interfaces in the Collection API

		| Interface       | Description                                   |
		| --------------- | --------------------------------------------- |
		| `Collection<E>` | Root interface for all collection types       |
		| `List<E>`       | Ordered collection, allows duplicates         |
		| `Set<E>`        | No duplicates, unordered                      |
		| `Queue<E>`      | FIFO structure for processing elements        |
		| `Deque<E>`      | Double-ended queue                            |
		| `Map<K, V>`     | Key-value pairs (not a subtype of Collection) |

	
	- Interface Hierarchy Diagram (Simplified)

		```
			Collection
				├── List

				│   └── Vector

				│   └── TreeSet

    				├── PriorityQueue

			Map (separate)

		```

## 🔍 Difference Between Array and Collection in Java

| Feature              | **Array**                                       | **Collection**                                                            |
| -------------------- | ----------------------------------------------- | ------------------------------------------------------------------------- |
| **Type**             | Fixed-size data structure                       | Dynamic data structure (part of Collection API)                           |
| **Size**             | Fixed once declared (e.g., `int[5]`)            | Grows/shrinks automatically                                               |
| **Type of Elements** | Can hold primitives (`int`, `char`) and objects | Can hold only objects (e.g., `Integer`, `String`)                         |
| **Performance**      | Faster for accessing elements by index          | Slightly slower due to overhead                                           |
| **Flexibility**      | Rigid, limited operations (just add/get)        | Provides advanced operations like `add`, `remove`, `sort`, `search`, etc. |
| **Data Structures**  | Only single or multidimensional arrays          | Many types: `List`, `Set`, `Map`, `Queue`, etc.                           |
| **Generics Support** | Not supported for primitive arrays              | Supports Generics (`List<String>`, `Set<Integer>`)                        |
| **Iteration**        | Manual loops (`for`, `while`)                   | Enhanced for-each, `Iterator`, `ListIterator`                             |
| **Utilities**        | Fewer built-in utilities                        | Rich utilities (`Collections.sort()`, `Collections.reverse()` etc.)       |

	- Why Use Collection Instead of Array?

		1.Dynamic Size:
			* Collections like `ArrayList` grow/shrink automatically.
			* Arrays are fixed in size and need manual resizing (copying to new arrays).

		2.Rich Functionality:
			* Collections provide **ready-made methods** like:
  			* `add()`, `remove()`, `contains()`, `sort()`, `clear()`, `isEmpty()` and more.

		3.Type Safety with Generics:
			* Collections can be type-safe using generics:

  				```
  					List<String> names = new ArrayList<>();
  				```

		4.Code Reusability:
			* The Collection framework is **interface-based**, making code modular and reusable.

		5.Advanced Data Structures:
			* Collections provide different structures: `List` (ordered), `Set` (no duplicates), `Map` (key-value), `Queue` (FIFO), etc.

	
		- Simple Example: Array vs. Collection

			- Using Array:

				```
					String[] fruits = new String[3];
					fruits[0] = "Apple";
					fruits[1] = "Banana";
					fruits[2] = "Mango";
					// No easy way to add/remove elements dynamically
				```

			- Using Collection (ArrayList):
	
				```
					import java.util.*;
					List<String> fruits = new ArrayList<>();
					fruits.add("Apple");
					fruits.add("Banana");
					fruits.add("Mango");
					fruits.remove("Banana");
					System.out.println(fruits); // [Apple, Mango]
				```
